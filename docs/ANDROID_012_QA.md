# Hub 0.12 — ссылка копии Perchance

12.11.2026. Исходный код и тесты: `35b15ba2bedd031642053604144e92b6bdd2ae5b`.

## Проблема и исправление

Команда Perchance `settings → duplicate it` оставляет редактор на странице оригинала. После создания копии в элементе `data-ref="duplicateGeneratorStatus"` появляется `Success!` со ссылкой `/<новое-имя>#edit`. В 0.11 диалог APK читал только `WebView.getUrl()`, поэтому подставлял оригинал. Поведение подтверждено чтением текущего публичного кода Perchance `appExtras.js`.

Новый `creation-link.js` наблюдает за ссылкой результата в основном документе Perchance и сообщает адрес нативному мастеру. Нативная часть проверяет HTTPS, точный домен, допустимый путь, отличие от оригинала и отсутствие дубликата в библиотеке. Ссылка сохраняется в необязательном поле `url` прежнего `pendingCreationV1`; старые черновики 0.11 остаются совместимыми. После перезапуска незавершённое создание открывает редактор копии.

При нажатии «Добавить в набор» APK дополнительно читает ссылку результата из текущего DOM и актуальный `location.href`. Если адрес новой игры не найден, поле остаётся пустым с пояснением. Оригинал автоматически не подставляется. Ручная вставка сохранена, проверка оригинала не отключалась.

Новый мост принимает только короткое сообщение с URL от главного документа точного origin `https://perchance.org` и только при активном создании. Фреймы игр и другие домены исключены. Он сохраняет предложенный URL, но не добавляет игру без подтверждения пользователя и не даёт доступ к файлам или учётным данным. Ограничения прежних мостов экспорта не менялись. Существующие страницы Perchance не изменялись, закрытые API не вызывались.

## Проверяемые сценарии

Тест повторяет фактическое поведение Perchance: после асинхронной операции на странице появляется ссылка результата, а адрес оригинала не меняется. Проверяются подстановка именно новой ссылки, сохранение до нажатия «Добавить в набор», перезапуск приложения, отдельные записи оригинала и копии, пустое поле до создания, запрет ручного добавления оригинала и прежние сценарии библиотеки.

Страницы в эмуляторе — локальные тестовые ответы на соответствующих URL. Ожидание загрузки этих страниц использует DOM; нажатия на кнопки страницы выполняются настоящими событиями касания по актуальным границам элементов. Нативные диалоги, поля и подтверждение добавления проверяются через Android accessibility. Живые копии в аккаунте пользователя при тестировании не создавались.
